# M09 Network + TV — отчёт

Дата: 2026-10-28. Машина: та же, что в M07/M08 (Ubuntu 24.04.5, проводная сеть, на ПК есть интерфейс локального VPN/прокси в режиме TUN). Ничего в сети не менялось: ни роутер, ни Wi-Fi/DHCP/DNS/firewall, ни Sunshine, ни ТВ; сеть не сканировалась.

## Архитектура
Registry — объекты; Monitoring — доступность и задержка объектов (новая метрика `net.latency`), история, журнал, инциденты; модуль Core `network` — только свои проверки (интернет, WAN роутера по UPnP IGD, Sunshine serverinfo) и их текущее состояние; Flutter — раздел «Сеть и ТВ», панель в доме, карточка в «Обзоре». Решения — ADR-015, описание — `NETWORK.md`.

## Реализовано
- Пять состояний (Доступен / Недоступен / Ошибка проверки / Не настроен / Нет данных) + «устарело»; подтверждение сбоя; время последней проверки и последнего успеха; задержка только там, где измерена (TCP/HTTP Monitoring, TLS/TCP интернета, HTTP Sunshine).
- Интернет по явным целям; **TLS-рукопожатие на :443** (локальный TUN-прокси иначе подделывает TCP-ответ).
- Роутер: доступность и задержка; WAN по документированному UPnP IGD (только `Get*`, только LAN-IP, тот же хост) или честное «только доступность».
- Sunshine: работает / идёт стрим / версия / веб-порт; «Открыть Sunshine» (только http/https, системный браузер); переход к ПК и ТВ, у каждого своё состояние.
- Журнал проверок (`net.*` в Monitoring, сбой не чаще раза в 5 мин), события смены состояния, инциденты `network:*` (один на ключ, закрываются при восстановлении), статусы проверок в «Источниках данных» Monitoring, `Redact` перед записью, приватные поля ответа Sunshine не читаются.
- `GET /network/overview`, `POST /network/check` (раз в 5 с); контракт 0.10.0; модуль выключаемый, без конфигурации — «не настроено».
- Flutter: сводка, карточки интернета, роутеров, Sunshine, ТВ, устройств, инциденты, журнал, «Проверить сейчас», состояния «нет связи с Core»/«устарело», переходы к карточке устройства, диагностике и общему журналу; панель в доме (роутер, ТВ, ПК со Sunshine); карточка в «Обзоре».

## Ограничения и UNVERIFIED
- WAN по UPnP на реальном роутере — UNVERIFIED (у роутера владельца нет документированного API веб-интерфейса; включён ли UPnP и его адрес — неизвестно).
- Задержка — время TCP/TLS/HTTP от Core, не ICMP ping (ICMP требует привилегий).
- `serverinfo` — протокол GameStream, а не публичный REST Sunshine; при смене формата будет «ответ не похож на Sunshine».
- Sunshine «стрим идёт» — по `state` Sunshine; какой клиент и с какой задержкой смотрит — недоступно без пароля Sunshine.
- ТВ на реальном оборудовании отвечал «хост недостижим» — проверено только отсутствие ответа; ответ включённой приставки — UNVERIFIED.
- Внеочередная проверка Monitoring для устройств запускается кнопкой, но интервал Monitoring (30 с по умолчанию) задаёт, как быстро обновится их состояние.
- Windows-клиент — UNVERIFIED (M10).

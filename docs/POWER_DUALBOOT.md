# AER Power — Wake-on-LAN, shutdown, смена Ubuntu/Windows

## Модель
Один физический ПК, два runtime profiles: Ubuntu и Windows (одновременно активна **только одна**). Состояния: OFF / WAKING / BOOTING / UBUNTU_ONLINE / WINDOWS_ONLINE / UNKNOWN / ERROR. Статус определяется heartbeat, не догадкой по открытым портам.

## Wake-on-LAN
Magic packet отправляет Core на **отдельном постоянно работающем** сервере в домашней LAN. Проверить BIOS/UEFI, сетевую карту, драйвер обеих ОС, WOL из S3/S4/S5; наличие линка в выключенном состоянии. Пока Core на том же единственном ПК, он **не может разбудить сам себя после выключения**. WoL из интернета отправляется через уже работающий Core с приватным доступом.

## Переключение ОС
- Ubuntu → Windows: one-shot GRUB entry (`grub-reboot`) **только после идентификации реального boot entry**, либо UEFI BootNext при подтверждённой конфигурации.
- Windows → Ubuntu: UEFI BootNext или проверенный отдельный механизм управления GRUB/Windows Boot Manager. Не выдавать универсальной команды, пока нет инвентаризации загрузчика.
- Все варианты требуют теста при физическом доступе, учёта Secure Boot, BitLocker Recovery, Fast Startup, незавершённых операций и пользовательских процессов.
- One-shot boot не равен гарантированной загрузке OS. При сбое AER Core фиксирует timeout и не делает бесконечные reboot loops.

## Команда как job
`plan` → проверка target OS, текущей OS, способа boot, прав и рисков → явное подтверждение → аудит → однократная команда → disconnect → wait heartbeat new OS → SUCCESS/FAILED/UNKNOWN.

## Безопасность
Раздельный least-privilege helper для разрешённых power операций; allowlist подписанных действий вместо произвольного root/sudo shell. Не конфигурировать sudo NOPASSWD на всё, не писать произвольные файлы EFI из UI.

## Приёмка
- WoL после полного выключения проверен минимум в каждой требуемой конфигурации питания.
- Двустороннее переключение успешно несколько раз при физическом присутствии, после чего тестируется удалённо.
- При ошибке не происходит повторных reboot без подтверждения, исходная загрузка сохраняет fallback.

# Scene Engine + Room Editor

## Цель
Изометрическая сцена с редактируемыми комнатами и предметами. Графика в нативном клиенте, Core хранит только сериализованные данные сцены. Flutter+Flame; Tiled подходит для authoring исходных карт, но итоговый встроенный редактор — свой.

## Схема
Home → Rooms → Layers → VisualObjects. Актуальная схема — **`docs/SCENE_FORMAT.md` / `contracts/scene.schema.json` v1** (M03): объект сцены имеет `id`, `roomId`, `assetId`, `position{x,y,z}`, `rotation`, `scale`, `layer`, `entityBinding{entityId,role}`, `visualState` (только демо), `metadata`; порядок отрисовки и область выбора вычисляются из геометрии, а не хранятся (прежние `deviceBinding`, `sortAnchor`, `hitArea` не используются). Никаких токенов/IP или executable scripts в scene JSON.

## Рендер
- Камера pan/zoom, изометрическая проекция, корректный z-order и occlusion.
- Устройство подсвечивается по normalized health; отдельно focus/selection state.
- Отключаемые эффекты и LOD; сцена не грузит Core и сохраняет работоспособность при offline.
- Asset pipeline: исходники, лицензии, атласы, низкое/высокое разрешение, fallback asset.

## Редактор
- Создать/клонировать/переименовать/архивировать комнату.
- Добавить предмет, переместить, rotate в поддерживаемых углах, align/snap; undo/redo, autosave draft, publish.
- Выбрать техобъект из Registry (или создать в wizard) → bind. Смена внешнего вида не меняет технический объект.
- Несколько визуальных объектов могут отображать одну сущность, техническая сущность может быть «без комнаты».
- Импорт/экспорт JSON+assets, schema migrations, validation, ревизии и безопасное восстановление прошлой версии.
- Устройство без доступа/провайдера остаётся в комнате с `UNKNOWN` или `UNSUPPORTED`, не исчезает.

## Flutter ↔ mobile
Общий JSON scene schema + assets/IDs. На iOS/Android отдельные рендереры либо совместимый общий движок **только после spike** по производительности и стоимости поддержки. Не утверждать, что SwiftUI/Compose нативно рендерят Flame.

## Редактор M04: как устроен

### Режимы
- **Просмотр** — как в M03: камера, выбор, карточки Registry. Мебель сдвинуть нельзя: перетаскивание двигает только камеру.
- **Строительство** — кнопка «Редактировать дом». Появляются верхняя панель (название дома, Просмотр/Строительство, Отменить, Повторить, Сохранить, Выйти), слева каталог/комнаты/объекты, справа свойства (или подсказки и история), снизу подсказки, масштаб, сетка и состояние сохранения.
- Выход с несохранёнными изменениями — выбор «Сохранить / Продолжить редактирование / Отменить изменения». Переключение разделов приложения (Обзор, Устройства) режим и правки не теряет.

### Архитектура (клиент, `apps/desktop/lib/src/scene/`)
| Слой | Файл | Что делает |
|---|---|---|
| Asset Catalog | `catalog/scene_catalog_data.dart`, `scene_catalog.dart` | единый справочник: 33 предмета (геометрия, категория, группа, тип размещения, привязка), 7 полов, 6 стен, 4 освещения, 5 отделок, виды комнат |
| Editor Commands | `editor/editor_commands.dart` | `AddRoom`, `UpdateRoom`, `DuplicateRoom`, `RemoveRoom`, `AddObject`, `UpdateObject`, `DuplicateObject`, `RemoveObject`, `BindEntity`, `UnbindEntity`; `EditHistory` (снимки, склейка серий, лимит 200) |
| Validation Engine | `editor/placement.dart` | типы размещения, опоры, пересечения с учётом высоты и полок, границы, комнаты |
| Editor Controller | `editor/editor_controller.dart` | режим, рабочая копия, выбор, инструменты, призраки, сохранение, конфликты, черновик |
| Editor Persistence | `editor/draft_store.dart` | атомарный локальный черновик, восстановление, ≤3 повреждённых копий |
| Renderer (без логики) | `render/editor_layer.dart` | рисует `EditorOverlay`: сетку, клетки под призраком, полупрозрачный призрак, рамки и ручки комнат, размеры |
| UI | `features/house/editor/*`, `features/house/house_view.dart` | панели, диалоги, горячие клавиши, жесты |

### Инструменты
- **Выбор**: клик — предмет (включая ковры) или комната. Первый клик только выделяет; перетаскивать можно **уже выделенный** предмет (защита от случайного сдвига). Перетаскивание по пустому месту — камера.
- **Размещение из каталога**: клик по карточке или перетаскивание карточки в сцену. Призрак следует за курсором с привязкой к сетке (шаг 0,5 клетки = 25 см, с Alt — 0,1), подсветка клеток зелёная/терракотовая, причина отказа — в строке состояния. R — поворот, Shift+клик — поставить ещё один, Esc — отмена.
- **Перенос**: призрак до отпускания; невалидное место — предмет остаётся на старом месте, история не меняется. Можно переносить между комнатами.
- **Поверхности**: предметы типа `surface` встают на крышку стола/тумбы или на полку стеллажа, на которую указывает курсор (высота подбирается сама); `wall` — на внешние задние стены (север/запад), высота по курсору; `overlay` (ковры) — под мебель.
- **Комнаты**: «Новая комната» (название, назначение, размер, пол, стены) → призрак комнаты у курсора, Enter — в предложенное место рядом с домом; перенос — перетаскивание выделенной комнаты (мебель едет вместе: координаты предметов локальные); размер — кружки на ближних краях или «Ширина/Длина» в свойствах; копия; удаление с предупреждением о числе предметов (и сколько из них привязаны к Registry). Наложение комнат и «предметы окажутся за стеной» запрещены. Перегородки и проёмы между соседними комнатами строятся автоматически (как в M03).

### Свойства
- Предмет: название (для привязанных — подпись), устройство (привязать/сменить/отвязать), положение (комната, на чём стоит, стрелки, поворот), размер (×0,5…×2), оформление (отделка), копия/удаление; «Дополнительно» — тип размещения, координаты, статус графики, id.
- Комната: название, назначение, ширина/длина, положение, пол, стены, освещение, число предметов, копия/удаление.

### Привязка к Registry
Мастер: поиск по Registry (активные, переключатель «Архив»), выбор, подтверждение. Перед привязкой сущность перечитывается (`GET /registry/entities/{id}`): если её удалили — понятная ошибка, привязки нет. В сцену пишется только UUID; имя и состояние приходят через Scene Binding (M03). Без Core кнопка неактивна (объяснение в подсказке); отвязать можно и офлайн. Перенос мебели привязку не трогает; удаление предмета не трогает объект Registry. Переименование в Registry видно после обновления привязок (при перезагрузке списка Registry и при переподключении).

### Сохранение
- Ручное: «Сохранить» / Ctrl+S → `PUT /scenes/{id}` с ревизией начала правок (демо-планировка → `POST`).
- Черновик: автоматически через 0,8 с после каждого изменения (`scene-draft.json` рядом с офлайн-кэшем). После перезапуска — плашка «Найден несохранённый черновик» (Восстановить / Удалить), с пометкой, если версия в Core с тех пор изменилась.
- Конфликт (409): «Загрузить актуальную» / «Сохранить как копию» / «Продолжить редактирование». Ничего не перезаписывается молча.
- Ошибка сети: сообщение, правки остаются в рабочей копии и черновике.

### Горячие клавиши (не перехватываются при вводе текста)
Esc — отменить действие/снять выделение · Delete — удалить (с подтверждением) · Ctrl+D — копия · Ctrl+S — сохранить · Ctrl+Z — отменить · Ctrl+Shift+Z / Ctrl+Y — повторить · R — повернуть · G — сетка · F — к выделенному · 0 — весь дом · +/− — масштаб · стрелки — сдвиг на шаг сетки (Shift — мелкий шаг).

## MVP порядок
1. одна статичная изометрическая комната (3–5 объектов), hit tests; 2. Camera; 3. Bind Registry; 4. Undo/redo; 5. Save/load; 6. Multiple rooms; 7. import assets/LOD.

## Приёмка
Тестами подтверждено: переименование/перемещение/перезапуск не ломают привязки; сохранённый дом открывается на следующем запуске; офлайн-сцена читаема; объект показывает семантику статуса, а не просто цвет.

# M06 Bots — отчёт

Дата: 2026-10-27. ПК разработки: Ubuntu 24.04, 12 потоков, 16 ГБ RAM; Go 1.27.3, Flutter 3.47.7. Все проверки шли против **изолированного** Core (временный каталог данных, порты 18797/18799). Объекты и боты, созданные проверками, помечены «(тест)», «(пример)» или «(синтетика)». Рабочие боты, контейнеры, службы и n8n пользователя не затрагивались.

## Что сделано
- Модуль Core `bots` (ADR-012): конфигурация бота поверх объекта Registry, задания, аудит действий, расширяемые адаптеры `heartbeat`, `telegram`, `process`, `systemd_user`, `docker`, `n8n`, фоновые опрос и очистка.
- Хуки Monitoring для других модулей, тайм-аут heartbeat у каждого объекта, проверки ботов без heartbeat через контейнер или URL, событие `bot_restarted` по новому `startedAt`. Добавлен индекс `mon_logs(entity_id, id)` (миграция monitoring v2).
- Раздел конфигурации `bots` с проверкой при старте и примером `deploy/core-bots.example.json`.
- Контракт 0.7.0 (`/bots/*`, `POST /bots/agent/jobs`, `BotStatus.version`).
- Python-библиотека heartbeat 0.2.0 (версия бота, задания, CPU/RAM на Linux) и тестовый бот `tools/bot-heartbeat/example_bot.py`.
- Flutter:
  - раздел «Боты»: список, поиск, фильтры, мастер из 4 шагов;
  - страница бота с 8 вкладками;
  - единый поток подтверждения действий;
  - панель бота в карточке объекта дома.
- Бенчмарк `cmd/aer-botbench`, документация, скриншоты (`docs/screenshots/m06`).

## Живая интеграция (тестовый бот)
Core запускал **тестовый** процесс `example_bot.py` (без Telegram, задания имитационные, каждое третье падает специально) через адаптер `process`. Проверено вживую:
- запуск по подтверждению — PID получен, heartbeat пришёл через 5 с, статус «В сети»;
- данные бота: версия `0.6.0-example`, uptime, CPU ≈0,2 %, RSS ≈22 МБ (из `/proc`), задания, строки stdout/stderr в журнале бота;
- повтор `Idempotency-Key` → `replayed: true`; без подтверждения → `PERMISSION_REQUIRED` с записью в аудит;
- перезапуск из UI → новый PID и событие `bot_restarted`; остановка и запуск из карточки в доме с подтверждением;
- после «Остановить» кнопка «Остановить» неактивна («Уже остановлен»);
- штатная остановка Core останавливает дочерний процесс (0 живых после выхода); после рестарта Core бот не запускается сам и через 20 с уходит в «Недоступен» с инцидентом;
- n8n — **заглушка API** (не настоящий n8n): workflows, 3 выполнения как задания, неудачное выполнение в журнале, повтор по подтверждению;
- Docker на машине не запущен: карточка показывает «Сокет /var/run/docker.sock не найден», команда завершается ошибкой с этой причиной.

**Найдено и исправлено замерами:**
- Логи бота при 50 000 строк — 148 мс. Причина — сортировка по `id` без индекса. После индекса `(entity_id, id)` — 1,0 мс.
- Параллельные запросы: p95 944 мс. Список пересчитывался каждым клиентом через единственное соединение SQLite. Сделан один листинг Registry вместо запроса на каждого бота, кэш на 2 с с объединением одновременных запросов. Стало: p95 61 мс.

Нагрузка здесь заметно выше домашней: клиент по умолчанию опрашивает раз в 10 с. Фоновая работа модуля:
- опрос n8n и адаптеров — раз в 60 с;
- CPU/RAM процессов — раз в 15 с, и только если процессы запущены Core;
- очистка — раз в час.

Простой Core с модулем Bots отдельно не замерялся: модуль ничего не делает, пока нет процессов и экземпляров n8n.

## Ограничения и что не проверено
- **Реальные Telegram-боты, n8n, Docker и systemd не подключались.**
  - n8n проверен на заглушке API, сверенной со спецификацией публичного API в исходниках n8n.
  - Docker — на поддельном API через unix-сокет; служба Docker на машине не запущена.
  - systemd — через подставной запуск команд.
- **Windows**: адаптер `process` собирается. Остановка там — принудительное завершение, метрик CPU/RAM нет (UNVERIFIED, M10).
- Core не «усыновляет» процессы, запущенные не им, и не запускает ботов сам после рестарта. Для ботов, которые должны жить без Core, используйте systemd `--user`, Docker или heartbeat.
- Повтор заданий есть только у n8n. Задания heartbeat-ботов повторять нечем: у Core нет канала к боту.
- Зависимости правятся в мастере только при создании. При редактировании — в «Устройствах» (связи Registry).
- Уровень строк вывода процесса угадывается по тексту (`ERROR`, `Traceback`, `WARN`…); строки длиннее 64 КБ не попадают в журнал.
- Персонаж-бот добавляется в комнату редактором M04 (каталог «Автоматизация → Бот-персонаж»). Живой тест привязывал уже стоящего персонажа демо-сцены.
- Демо-сцена по-прежнему показывает помеченные тестовые состояния у непривязанных объектов.

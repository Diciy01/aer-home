# ADR-010: Редактор дома (M04)

**Статус:** ACCEPTED (2026-10-27). Контракт `openapi.yaml` 0.4.0 → **0.5.0** (аддитивно: схема сцены остаётся v1).

## Контекст
M04 добавляет визуальный редактор комнат, мебели, оборудования и привязок к Registry. Требования: два независимых режима (просмотр / строительство), Undo/Redo, проверка размещения с учётом высоты, черновик с восстановлением, защита от конфликтов ревизий, данные-материалы, рендерер без логики редактирования, 60 к/с.

## Решения

1. **Слои клиента** (`apps/desktop/lib/src/scene/`):
   - `catalog/` — **единственный** каталог: ассеты (геометрия, категория, тип размещения, «можно привязать»), материалы пола/стен, пресеты освещения, отделки. Это таблица данных в форме JSON (`scene_catalog_data.dart`) + парсер. Тест сверяет геометрию с ассетами демо-сцены, второго справочника нет.
   - `editor/editor_commands.dart` — **Editor Commands**: каждое действие — объект-команда с чистым `apply(doc)` поверх `SceneEdits` (результат всегда проходит валидацию формата). id новых комнат/объектов фиксируются при создании команды → повтор детерминирован.
   - `EditHistory` — **снимки неизменяемых документов** (before/after). Undo возвращает ровно тот документ, с которого начиналась команда: повреждение модели многократной отменой невозможно по построению. Серии быстрых правок одного вида (ползунок масштаба, стрелки, переименование) склеиваются по `mergeKey` в окне 2 с; перетаскивание — одна запись (коммит только на отпускании). Лимит 200 шагов.
   - `editor/placement.dart` — **Validation Engine**: типы размещения `floor` / `surface` / `wall` / `overlay`; опора (на полу, на крышке, на полке, на стене), пересечения 3D-объёмов с исключениями (контейнер-полки, ковры, настенные — только с настенными), границы комнаты, размеры, наложение комнат, «предметы окажутся за стеной».
   - `editor/editor_controller.dart` — **Editor Controller**: режим, рабочая копия, выбор, инструменты (выбор, размещение, перенос, новая комната, перенос/размер комнаты), призраки предпросмотра, сохранение/конфликты, черновик. Ввод принимает в мировых пикселях — от мыши/тача не зависит.
   - `editor/draft_store.dart` — **Editor Persistence**: черновик `scene-draft.json` рядом с офлайн-кэшем, атомарная запись (tmp + rename), автосохранение через 0,8 с после правки, повреждённый файл откладывается, хранится не более 3 повреждённых копий (то же ограничение добавлено кэшу сцены).
   - `render/editor_layer.dart` — рендерер получает только данные `EditorOverlay` (сетка, призрак, рамка комнаты, скрытый объект) и рисует их. **Логики редактирования во Flame нет.**
   - UI — `features/house/editor/` (панели, диалоги, превью ассетов); `HouseView` связывает ввод с контроллером.
2. **Рабочая копия показывается через тот же путь, что и сохранённая сцена**: `SceneController.previewDocument()` строит layout/представления, но не трогает Core и **не пишет черновик в офлайн-кэш** (кэш получает только сохранённые версии). Во время редактирования переподключение к Core обновляет привязки, но не перезагружает документ поверх правок.
3. **Сохранение**: `PUT /scenes/{id}` с ревизией, *с которой начались правки* (`baseRevision`, в т.ч. из восстановленного черновика). 409 → диалог: загрузить актуальную / сохранить копией (`POST /scenes` с новым `sceneId`, копия становится активной сценой) / продолжить. Молчаливой перезаписи нет. Активная сцена при нескольких сценах в Core — та, что в локальном кэше.
4. **Материалы — данные**: Core и клиент проверяют только форму идентификатора (`^[a-z][a-z0-9_]{0,31}$`) вместо перечислений; неизвестный клиенту материал рисуется нейтральным запасным. Добавлено необязательное `style.light` (пресет освещения). Отделка предмета — ключ `metadata.finish` (формат v1 уже допускает metadata). Поле `texture` у материалов зарезервировано под будущие текстуры.
5. **Производительность**: призрак и сетка рисуются вектором поверх **растрового кэша** дома (кэш принудительно используется, пока идёт предпросмотр); перемещаемый объект один раз убирается из кэшированной картинки на старте перетаскивания. Обновление призрака идёт через отдельный `previewTick` — панели не перестраиваются на каждое движение мыши (build 7 → 1,1 мс). Превью каталога рендерятся один раз в текстуры.
6. **GameWidget не перемонтируется** при смене режима (ключевой слот сцены): перемонтирование отсоединяло Flame-игру и освобождало кэш. Ресурсы игры освобождаются только в `dispose` вида.

## Альтернативы
- Undo через обратные операции (inverse commands) — отвергнуто: больше кода и риск расхождения модели; документы маленькие (200 объектов ≈ 58 КБ JSON), снимки дешевле и надёжнее.
- Логика перетаскивания внутри Flame-компонентов — отвергнуто требованием «рендерер — только отображение» и ради будущих мобильных клиентов.
- Расширять перечисления материалов в Core при каждом новом материале — отвергнуто: требование «материалы определяются данными».
- Повышать `schemaVersion` до 2 — не нужно: изменения аддитивные, каждый документ 0.4.0/v1 остаётся валидным; старые клиенты в эксплуатации отсутствуют.

## Последствия
- Undo/Redo на 200 объектах стоит ~22 мс на шаг (пересборка layout, картинки и текстуры) — одиночная задержка ≈ 1 кадр; при 35 объектах ~7 мс.
- Каталог пока встроен в приложение; пользовательские каталоги/текстуры подключаются заменой источника данных без изменения логики.
- Импорт/экспорт JSON сцены (упоминался в ROADMAP для M04) в задание M04 не входил и отложен.

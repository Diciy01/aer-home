# ADR-001: Go + SQLite для AER Core

**Статус:** ACCEPTED (2026-10-26, M01)

## Контекст
Core должен работать на слабом сервере (4 ГБ RAM, неизвестный CPU/диск), быть одним процессом и переноситься с основного ПК без переписывания клиентов.

## Решение
- Go 1.27, стандартный `net/http` (маршрутизация по методу из ServeMux), `log/slog`. Без web-фреймворков.
- SQLite через **modernc.org/sqlite v1.61.0** (pure Go, BSD-3): без cgo → кросс-компиляция linux/amd64, linux/arm64, windows.
- Режим WAL, `busy_timeout=5000`, `foreign_keys=ON`, `synchronous=NORMAL`, один пул-коннект (один писатель).
- Миграции: forward-only, по модулям (`schema_migrations(module, version, name)`), каждая в транзакции; отказ стартовать при более новой схеме или переименованной миграции.

## Альтернативы
- `mattn/go-sqlite3` — быстрее, но cgo усложняет кросс-сборку.
- PostgreSQL — избыточен для одного пользователя (docs/ARCHITECTURE.md).

## Последствия
- Измерено: бинарник 16.9 МБ, RSS в простое ≈ 13.5 МБ.
- Один коннект сериализует чтения; при росте нагрузки — отдельный read-пул (WAL это допускает).
- Откат схемы не автоматический: перед миграциями в M13 — бэкап файла БД.

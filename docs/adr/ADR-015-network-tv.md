# ADR-015: Сеть и ТВ — модуль наблюдения поверх Registry и Monitoring (M09)

**Статус:** ACCEPTED (2026-10-28). Контракт 0.9.0 → **0.10.0** (аддитивно: `/network/*`, метрика Monitoring `net.latency`, события/логи/инциденты Monitoring без объекта).

## Контекст
Нужен единый вид домашней сети и ТВ-стриминга: роутер, интернет, сетевые устройства, Sunshine, телевизор, ошибки и журнал. Нельзя: сканировать сеть, менять настройки роутера/Wi-Fi/DHCP/DNS/firewall, управлять Sunshine, хранить второй журнал/метрики/инциденты, выдумывать API устройств. Роутер владельца — потребительская модель без документированного локального API; Sunshine работает на ПК; ТВ — отдельное устройство.

## Решение
1. **Monitoring наблюдает устройства** (как с M05): доступность роутера, сетевых устройств и ТВ — его TCP/HTTP-проверки объектов Registry. Новое: задержка этих проверок сохраняется метрикой `net.latency` (время TCP-соединения или HTTP-ответа от Core; не ICMP — для ICMP нужны привилегии).
2. **Модуль Core `network`** выполняет только свои интеграционные проверки и хранит лишь их текущее состояние (`net_checks`):
   - **интернет** — явно заданные цели `network.internet.targets`: на порту 443 (или с префиксом `tls://`) — TCP-соединение **и TLS-рукопожатие** (сертификат не сверяется: данные не передаются, нужен лишь факт ответа реального TLS-сервера), на других портах (или `tcp://`) — TCP-соединение, где отказ в соединении считается ответом удалённого хоста. Ответ хотя бы одной цели = доступен; DNS-ошибки всех целей = «ошибка проверки»; пусто = «не настроено». TLS обязателен потому, что локальный VPN/прокси в режиме TUN принимает любое TCP-соединение сам (найдено на основном ПК: TCP 0,2–1,4 мс, настоящее рукопожатие ≈300 мс);
   - **роутер** — только через документированный стандарт **UPnP IGD** и только если владелец указал URL описания (`network.routers[].upnpUrl`): действия `GetStatusInfo` и `GetCommonLinkProperties` (чтение); адреса — только IP домашней сети, управляющий URL — только тот же хост; внешний IP не запрашивается. Без адаптера карточка честно говорит «только доступность и задержка»;
   - **Sunshine** — `GET /serverinfo` по HTTP-порту GameStream (тот же интерфейс, что использует Moonlight; без авторизации). Разбираются только `state` (`*_BUSY` = идёт стрим), `appversion`, `currentgame`; имя хоста, MAC, LocalIP и uniqueid не читаются и не хранятся. Веб-интерфейс — только TCP-доступность порта; открывается в браузере владельцем.
3. **Пять состояний**: `up` (Доступен), `down` (Недоступен), `error` (Ошибка проверки), `unconfigured` (Не настроен), `unknown` (нет данных) + признак `stale` (последняя проверка старше трёх интервалов). Отказ подтверждается `failuresBeforeDown` проверками подряд; отсутствие ответа не выдаётся за выключенное устройство.
4. **История, журнал, инциденты — Monitoring**: события `net_down|net_error|net_recovered`, логи источников `net.internet|net.router_wan|net.sunshine` (сбой пишется при смене состояния и не чаще раза в 5 минут, после очистки `Redact`), инциденты `network:<ключ>` — открываются один раз при переходе в сбой и закрываются при восстановлении; ротация и сроки — правила Monitoring. Интернет не является объектом Registry: его записи хранятся без `entity_id`.
5. **Sunshine и ТВ раздельны**: у Sunshine — свой объект (служба или ПК, `entityId`) и отдельно телевизор (`tvEntityId`), состояние каждого — из своего источника; одно не доказывает другое.
6. **Конфигурация только в Core** (`network` в JSON-конфиге); пустая конфигурация = «не настроено», модуль можно выключить — остальные модули работают.

## Альтернативы
- API веб-интерфейса роутера — недокументирован (зашифрованный проприетарный протокол), отклонено; SNMP — обычно отсутствует на домашних роутерах, кандидат на будущее.
- Обнаружение устройств (SSDP, ARP-скан) — запрещено (не сканировать сеть).
- `GET /api/*` Sunshine — требует пароль владельца; не нужен для состояния, отклонено.
- Beszel/Uptime Kuma — лишние службы ради TCP-проверок, отклонено.

## Последствия
- На реальном роутере UPnP не проверялся (неизвестно, включён ли): UNVERIFIED; доступность роутера и ТВ проверяется Monitoring.
- `serverinfo` — протокол GameStream, а не публичный REST Sunshine; при смене формата модуль покажет «ответ не похож на Sunshine», а не ложное «работает».

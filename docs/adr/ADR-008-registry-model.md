# ADR-008: Модель Registry

**Статус:** ACCEPTED (2026-10-26, M02). Контракт `contracts/openapi.yaml` 0.2.0 → **0.3.0**.

## Контекст
Registry — единый источник сведений об объектах дома. Нужны расширяемые типы, возможности отдельно от типа, типизированные связи, отсутствие секретов и визуальных данных, стабильный интерфейс для M03+ модулей.

## Решение
1. **Каталог** (`core/internal/modules/registry/catalog.go`): типы, возможности и виды связей — данные. Новый тип = одна запись `RegisterType` (лейбл, группа, иконка, режим адреса, возможности по умолчанию). API `/registry/types` и мастер на клиенте строятся из каталога, клиент не требует изменений. Неизвестная клиенту иконка → нейтральный fallback.
2. **Тип ≠ возможности.** При создании возможности копируются из типа (`source=type_default`), затем живут отдельно (`registry_entity_capabilities`, `PUT …/capabilities`). Registry только *объявляет* возможности; исполнение — модули Monitoring/Remote/Power/Bots.
3. **Сущность:** UUID, name, type, description, icon, tags, parentId, discovery, address, secretRefs, attributes (JSON-объект), capabilities, revision, createdAt/updatedAt, archived/archivedAt. Поля статуса **нет**: здоровье — Monitoring (отличие от черновика 0.1).
4. **Секреты:** только ссылки `env:|keyring:|file:|vault:`. Ключи атрибутов, похожие на секреты (password, token, secret, api_key, private_key, credential…), и учётные данные в адресе (`user:pass@`, `user@host`) отклоняются.
5. **Связи:** направленные `from <kind> to`; виды runs_on, hosted_by, installed_on (группа *placement*, ацикличная), depends_on (группа *dependency*, ацикличная), connected_to, controls, custom (с подписью; циклы допустимы). Цикл проверяется рекурсивным CTE внутри группы → 409 `reason=cycle`. Самосвязь и дубликаты запрещены. Иерархия `parentId` (например, Ubuntu и Windows внутри одного ПК) тоже проверяется на циклы.
6. **Оптимистическая блокировка:** каждое изменение требует `revision`; несовпадение → 409 `reason=revision_mismatch`, `currentRevision`. Связи не меняют revision сущности.
7. **Без физического удаления:** archive/restore. Архивные объекты читаются по id, скрыты из списка по умолчанию, не редактируются, к ним нельзя создавать новые связи/детей. Удаляются только связи (это не объекты).
8. **Поиск:** Unicode-регистронезависимый (`search_text` в нижнем регистре в Go — SQLite LIKE понимает регистр только ASCII), все слова запроса должны совпасть, `%`/`_` экранируются. Сортировка по `name_key`.
9. **Интерфейс для модулей:** `registry.Reader` (Get, List, Relations, Catalog). Scene хранит координаты, Monitoring — метрики, Remote — сессии в своих таблицах по `entityId`; таблицы `registry_*` другие модули не читают.

## Альтернативы
- Тип как enum в БД/коде клиента — отвергнуто: добавление типа трогает много файлов.
- Возможности только из типа — отвергнуто: у конкретного ПК может не быть WoL.
- Жёсткое удаление с каскадом — отвергнуто: потеря истории, риск сломать будущие ссылки Scene/Incidents.

## Последствия
- Пользовательские (runtime) типы без пересборки Core — не сделано; каталог расширяется в коде. Возможное развитие: таблица пользовательских типов с тем же `RegisterType`.
- Попадание секрета в `description` технически не блокируется (свободный текст) — UI предупреждает в адресе; redaction логов — M05.

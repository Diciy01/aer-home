# ADR-016: Нативный Android-клиент поверх существующего Core (M12)

**Статус:** ACCEPTED (2026-10-28). Контракт **не меняется** (0.10.0): клиент использует только существующие маршруты.

## Контекст
Нужен мобильный клиент AER HOME на Kotlin/Jetpack Compose с двумя режимами («Дом» и «Классика»), а не упрощённая копия со своей архитектурой. Нельзя: дублировать бизнес-логику Core, держать свою базу устройств, придумывать API, менять архитектуру ради клиента. Core не имеет TLS; доступ извне — только из домашней сети или приватной overlay-сети (`SECURITY.md`). Модель авторизации MVP — один bearer-токен владельца (ADR-007).

## Решение
1. **Три Gradle-модуля** в `apps/android`:
   - `:core-api` — чистый Kotlin/JVM: HTTP-клиент конверта ADR-007, DTO по `contracts/openapi.yaml`, снимок состояния дома с признаком устаревания (`HomeRepository`), протокол «подтвердить → выполнить» (`ActionFlow`), проверка адреса Core, тексты состояний. Тестируется на JVM против фейкового HTTP-сервера и **реальных ответов Core** (фикстуры со стенда).
   - `:scene` — чистый Kotlin: формат сцены v1 (тот же JSON, что хранит Core и редактирует desktop), перенос геометрии desktop-рендерера (`iso.dart`, `scene_layout.dart`, привязки, камера) с тестами-зеркалами desktop-тестов. Второго формата сцены нет.
   - `:app` — Compose-интерфейс по функциональным пакетам (`ui/screens`, `ui/house`, `ui/actions`, `data`).
2. **Источник истины — Core.** Устройства — Registry, состояния/журнал/инциденты — Monitoring, сеть — `/network/*`, питание и боты — их модули. Клиент хранит только адрес Core, режим интерфейса, зашифрованный токен и кэш последней сцены (для офлайн-просмотра, повреждённый откладывается).
3. **Авторизация без изменений сервера:** пользователь вводит адрес Core и токен владельца (`core.token`). Токен шифруется AES-256-GCM ключом из AndroidKeyStore (неэкспортируемым), в SharedPreferences лежит только шифротекст; резервное копирование и перенос данных приложения отключены. При неудаче шифрования токен **не** сохраняется открытым текстом.
4. **Транспорт:** http разрешён (Core без TLS), но клиент **отказывается** отправлять токен по http на публичный адрес и предупреждает для адресов домашней сети; loopback, Tailscale (100.64/10, `*.ts.net`) и https — без предупреждения. Android не умеет ограничить cleartext диапазоном IP, поэтому правило — в `core-api` (`Endpoint.kt`) и покрыто тестами.
5. **Действия только через протокол Core:** доступность действий, условия, риски и одноразовый токен подтверждения выдаёт Core; клиент показывает их и отправляет выполнение с `Idempotency-Key` (один ключ на намерение; повтор после потерянного ответа — с тем же ключом). Задания питания отслеживаются до итогового состояния; `SIMULATED` никогда не показывается как выполненное.
6. **Сцена на телефоне** — тот же документ из `GET /scenes`; рисуется упрощённо (затенённые параллелепипеды вместо процедурных рисунков desktop), но с той же проекцией, порядком отрисовки и областями касания. Нет сцены в Core → встроенная демо-планировка (`examples/home.scene.json`, копируется при сборке) с явной пометкой; нет связи → последняя полученная сцена с пометкой.
7. **Версии** — как в шаблоне Flutter 3.47.7 (Gradle 9.3.1, AGP 9.1.0, Kotlin 2.4.0); библиотеки — новейшие, совместимые с `compileSdk 36` (проверено по `minCompileSdk` AAR): Compose BOM 2026.06.01, lifecycle 2.10.0, OkHttp 5.4.0.

## Альтернативы
- Flutter-клиент для Android (переиспользовать desktop целиком) — противоречит требованию нативного Kotlin/Compose (OVERVIEW.md); отклонено.
- Встроить Flame-рендерер через Flutter add-to-app — тяжёлая зависимость ради одного экрана; отклонено в пользу переноса геометрии в `:scene`.
- Device-scoped токены в Core до M12 — правильное направление (ADR-007 «Отложено»), но это изменение сервера и модели авторизации; не нужно для работы в домашней сети/Tailscale. Перенесено (см. «Последствия»).
- EncryptedSharedPreferences — библиотека устарела; прямой Keystore проще и без зависимости.

## Последствия
- Телефон получает **токен владельца** с полными правами. Перед доступом к Core вне доверенной сети нужны device-scoped учётные данные с отзывом (ADR-007) — UNVERIFIED/TODO.
- Чтобы телефон видел Core, Core должен работать в режиме `local`/`server` и слушать адрес LAN или Tailscale; режим `development` слушает только loopback (в эмуляторе доступен как `10.0.2.2`).
- Редактирование сцены на телефоне не реализовано: только просмотр, навигация, выбор и переход к устройствам.

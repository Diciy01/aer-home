# M05 Monitoring — проверка и измерения

Дата: 2026-10-27. ПК разработки: Ubuntu 24.04, 12 потоков, 16 ГБ RAM; Go 1.27.3, Flutter 3.47.7. Все проверки — против изолированного Core (временный `AER_DATA_DIR`); объекты Registry, созданные проверками, помечены «(тест)». Нагрузочные цифры получены на **синтетических данных** (`aer-monbench`) и описывают хранилище на этой машине, а не реальный дом.

## Живая проверка полного пути
Агент → Core → SQLite → API → Flutter → отображение:
1. Настоящий `aer-agent` на этой Ubuntu (интервал 5 с) с учётными данными, созданными через API, присылал реальные CPU, RAM, swap, диски, сеть, температуры CPU (k10temp) и GPU (amdgpu), загрузку GPU, число процессов, состояние служб `ssh`, `cron` и journald warning+.
2. Core показал устройство «есть проблемы» — служба `ssh.service` на этой машине действительно не запущена (порог «служба не работает»).
3. Агент остановлен → через 2 проверки «недоступен», последний контакт — время последнего отчёта, открыт инцидент, уведомление. Агент запущен → восстановление, инцидент закрыт автоматически, уведомление о восстановлении.
4. Core остановлен на ~1 мин → агент копил данные (182 значения, 0 потерянных), затем сам переподключился и досылал очередь; на графике CPU разрыв на время остановки агента и непрерывные данные за время остановки Core.
5. Heartbeat бота (`aer_heartbeat.py`): «в сети» → после ошибки зависимости «есть проблемы», текст ошибки с вырезанным токеном → без heartbeat «недоступен» с инцидентом.
6. Docker на этой машине не запущен: интеграция честно показывает «сокет не найден: служба Docker не запущена или не установлена», контейнер в Registry — «неизвестно» с этой причиной. Работа с Docker проверена тестами на поддельном Docker Engine API через unix-сокет (список, inspect, stats, логи, OOMKilled, потеря связи).
7. Приложение (`integration_test/monitoring_live_test.dart`): обзор, карточки, диагностика (обзор, метрики, график, события), инциденты с подтверждением, журнал (поиск, детали), агенты и Docker, уведомления, дом (значок ПК из мониторинга, карточка с последним контактом и кнопкой «Диагностика»). С остановленным Core (`AER_EXPECT_OFFLINE=1`): последний снимок с временем и пометкой «устарело», действия неактивны.

## Не сделано / ограничения
- Агент Windows не запускался на реальной Windows (UNVERIFIED); температура CPU на Windows — `unsupported`.
- Docker проверен на поддельном API: на этой машине служба Docker не запущена, включать её в рамках M05 не разрешено.
- Реальные Telegram-уведомления не отправлялись (интеграция проверена на тестовом HTTP-сервере); реальные боты не подключались (протокол проверен скриптом heartbeat).
- ICMP-ping не реализован намеренно (нужны привилегии; молчание ICMP не доказательство) — для сетевых устройств TCP-достижимость.
- Агенты не установлены как службы (по заданию — только вручную, шаблоны в `deploy/agent/`).
- Демо-сцена разработки по-прежнему содержит помеченные тестовые состояния; для привязанных объектов показывается реальное состояние мониторинга.

# Работа одному через Claude Code

## Режим
1. Задача начинается с номера milestone и конкретной области файлов.
2. Claude формирует мини-план, риски, границы, тесты и подтверждает отсутствие опасных операций.
3. Выполняет минимальные изменения, отдельно тесты и документацию, отчёт.
4. Владелец просматривает diff, проверяет демо, затем коммитит. Не переходить к следующему пункту самостоятельно.
5. На каждое новое решение — ADR с альтернативами и последствиями.

## Шаблон задания
```text
Работаем над AER HOME, задача [Mxx / часть].
Прочитай CLAUDE.md, docs/ARCHITECTURE.md, docs/MODULES.md, docs/ROADMAP.md, нужную спецификацию.
Цель: [...]. Разрешены изменения только в [...].
Не трогай живую сеть, загрузчик, роутер, диски, работающие сервисы.
Сначала дай план и acceptance; затем реализуй минимальный срез с tests.
После работы: changed files, tests results, remaining limitations, migration notes, next small step.
Не называй mock-тест подтверждением работы физического устройства.
```

## Первый промпт
```text
Прочитай весь пакет AER HOME. Начни M00 Discovery/feasibility: проверь доступность Flutter/Dart/Go, Git, текущий репозиторий и ОС в read-only; составь ADR candidates, список непроверенных возможностей, тестовую матрицу и пошаговый план M01. Не устанавливай ничего, не перезагружай ОС, не меняй сеть и не начинай писать приложение до представления плана. Никогда не форматируй существующие диски и не затрагивай другие проекты.
```

## Commit discipline
Conventional commits `feat(scene): ...`, `test(registry): ...`; семантические версии contracts, unit+integration tests before marking DONE. Документировать блокеры Windows/macOS/server hardware.

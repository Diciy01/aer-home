# Product requirements: AER HOME

## Проблема
Несвязанные инструменты мониторинга, управления домашним ПК, сервером, ботами и медиа. Нужно одно уютное приложение, в котором видно состояние и можно диагностировать/управлять без запоминания IP, портов и команд.

## Цели
- Единое пространство «дом» + классическая операционная панель; равные возможности.
- Вручную добавить объект за 1–3 коротких шага; автодетект только при поддержке и согласии.
- Понимать **что сломалось, когда, на что повлияло**, видеть исходные логи, а не только цветной значок.
- С Windows на работе или Ubuntu дома: полный удалённый доступ к текущей ОС основного ПК; текстовый clipboard, файлы, управление вводом.
- С мобильного: запущенные приложения, разрешённые окна/специализированные API-панели, **без полного desktop**.
- Удалённый WoL и контролируемое переключение dual-boot по явному подтверждению.
- Мониторинг Python/Telegram ботов, Docker, сервисов и фоновых заданий.
- Работать локально без отдельного сервера на этапе разработки; впоследствии перенести Core на маломощный ПК.

## Не цели MVP
- Нативное приложение iOS — **CANCELLED / OUT OF SCOPE** по решению владельца 2026-10-28; не является условием завершения проекта. Существующие материалы сохраняются. Возможный веб-интерфейс для iPhone — необязательная будущая идея без этапа, сроков и обязательств.
- Публичный SaaS, биллинг, учётки чужих домохозяйств.
- Собственный медиасервер, фотооблако, массивный NAS.
- Переписывание RDP/видеокодеков с нуля.
- Полноценная 3D Sims с персонажами, физикой и симуляцией бытовой жизни.
- Автоматическое исправление ошибок без согласия.

## Целевые устройства
- Домашний dual-boot ПК Ubuntu 24.04 Wayland и Windows, Ethernet; DHCP reservation 192.0.2.154 (конфигурируемый пример, **не зашивать**).
- Домашний роутер, Android TV-приставка, Sunshine/Moonlight, VPN/прокси, будущий физический сервер, Docker/Python/Telegram bots.
- Поддерживаемые платформы: Windows, Linux (включая Ubuntu Desktop), Android и Ubuntu Server для Core/Gateway. Нативный iOS исключён из объёма проекта.

## Сценарии / user stories
1. Изометрия → кабинет → нажать ПК → статус, логи, удалённое подключение.
2. Удалёнка с PC → полный desktop, ввод, sync текста, отправка/получение файлов; Windows↔Ubuntu в сеансе при согласии.
3. Android → безопасные API-панели; Remote Apps только после доказанной изоляции разрешённого окна, без fallback на полный desktop. Текущий статус — UNSUPPORTED; iOS для этого сценария не требуется.
4. ПК выключен → сервер отправляет WoL → ожидание heartbeat → агент активной ОС.
5. PICO отвечает в Telegram, но не выполняет задачу → heartbeat/task failure → инцидент → логи и диагностика.
6. Добавить новый бот через имя + источник Docker/HTTP/agent/manual, поместить в комнату, настроить отображение.
7. Редактировать комнаты без изменения кода; сохранить layout и экспортировать.
8. Нет сети/Core → офлайн-последнее состояние с маркировкой времени и без опасных действий.

## Словарь статусов
ONLINE, DEGRADED, ERROR, OFFLINE, UNKNOWN, MAINTENANCE, STARTING. Не смешивать OFFLINE с выключенной альтернативной dual-boot ОС. Все метрики снабжать временем последнего измерения.

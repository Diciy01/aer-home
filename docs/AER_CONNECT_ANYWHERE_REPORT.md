# AER Connect Anywhere — отчёт (M14.4, 2026-10-29)

Статус: **реализовано и проверено автоматически, synthetic и на этой Windows 11 Pro;
внешний доступ НЕ готов к публикации** до аудита развёрнутого сервера и живых
проверок с отдельного согласия. M14.4 остаётся IN_PROGRESS. Push не выполнялся.

Решение — `adr/ADR-018-connect-anywhere.md`, пользователю — `AER_CONNECT.md`,
серверу — `SERVER_UBUNTU.md`.

## Что работает

Установил AER Connect → один раз ввёл адрес домашнего Gateway, сверил отпечаток и
ввёл код регистрации владельца → компьютер получил постоянный ID и показывает
временный пароль → на другом ПК ввели ID и пароль → на хосте подтвердили → рабочий
стол открылся в AER Connect через собственный Gateway. Каждая установка — и Host,
и Viewer. На клиентах не нужны IP, порты, VPN и настройка роутера.

`458e3ae` в истории. Фактическая матрица:

| Возможность | До | После |

| Сопряжение клиентов `aerc1`, билеты, отзыв | есть | сохранено; устройство-Viewer — тоже клиент `aerc1` |

| Единый UI Host+Viewer | нет (только Viewer) | «Этот компьютер» + «Подключиться» |
| Клонирование установки | нет | `instance`, статус `conflict` |
| Ubuntu Server deploy | только пример конфига | systemd, `aer-admin`, backup/restore, health |

## Реализовано

- **Core** (`modules/remote/devices.go`, миграция 3, контракт 0.12.0): коды регистрации
  (SHA-256, N устройств, срок), регистрация (Registry `computer` + агент `remote` +
  клиент `aerc1` + номер, откат при сбое), список/отзыв устройств, challenge
  (одноразовая попытка 60 с, 128 бит), connect с ожиданием вердикта хоста (20 с),
  `auth_state` сеанса, запрет событий до проверки пароля, запрет беспарольных
  сеансов к устройствам, лимиты попыток, обнаружение клона, очистка счётчиков.
- **Gateway**: `POST /gw/v1/devices/enroll` (лимит как у сопряжения),
  `GET /gw/v1/devices/me`, `POST /gw/v1/connect/challenge`, `POST /gw/v1/connect`.
- **Engine Go** (`remoteengine/connectauth.go`): запечатывание пароля, PBKDF2-верификатор,
  генерация временных паролей и номеров; **Engine Dart** (`connect_auth.dart`) —
  то же для Viewer, побайтно совпадает с Go (общий тест-вектор).
- **Host**: `remotehost.Agent` — режим устройства (токен в памяти, `features`,
  `instance`, проверка до согласия, статусы связи, `StopSession`, backoff с
  jitter 1 с…60 с); `connecthost` — Guard (временный/постоянный пароль, replay,
  блокировка 5/10 мин → 15 мин и смена пароля, однократность временного пароля),
  JSON-строковый протокол по stdio; `aer-connect-host` (keygen, instance, отказ
  elevated, GUI subsystem — без консольного окна).
- **AER Connect**: регистрация, «Этот компьютер» (ID, пароль, статус, входящие
  вкл/выкл, постоянный пароль, права: ввод, буфер, папка файлов, автозапуск,
  индикатор и «Остановить»), «Подключиться» (ID+пароль, ошибки, ожидание
  подтверждения, встроенный viewer, завершение, переподключение), отзыв,
  «Удалить регистрацию», legacy-сопряжение сохранено, `connect.json`-preset.
- **Пакет Windows**: Host-компоненты по allow-list, отказ при несовпадении общих
  DLL, `install.ps1 -Upgrade`, удаление своей записи автозапуска.
- **Ubuntu**: `deploy/ubuntu/*` (юниты с hardening и разными пользователями,
  конфиги, `install-server.sh`, `aer-admin`).
- **Стенд**: `aer-remotelab -anywhere` (устройство с настоящим рантаймом
  `connecthost`, fake RDP или synthetic Windows Host).

## Не проверено (UNVERIFIED)

1. **Живой захват/ввод** в пользовательскую сессию через новый Host-рантайм: эта
   сессия запущена с повышенными правами, Host честно отказывается; повторная живая
   приёмка DXGI/SendInput требует отдельного согласия и обычного пользователя.
   Прежняя ограниченная приёмка `bd12743` (кадры, мышь, клавиша A, отзыв, Stop) не
   распространяется автоматически на новый путь запуска.
2. Реальные кириллица с клавиатуры, двусторонний OS clipboard, файлы, lock/UAC,
   длительные сеансы, утечки памяти на долгих прогонах, производительность.
3. **Windows Home** — отсутствует такая система. Ожидаемое поведение: тот же
   DXGI/SendInput Host без встроенного RDP Windows; отличий кода нет.
4. **REAL WAN**: два ПК за NAT/CG-NAT/мобильным интернетом, смена IP клиента,
   реальная задержка. Логика переподключения и backoff проверена только на loopback.
   NAT-изоляция контейнерами/namespaces на этой Windows недоступна.
5. **Ubuntu Server**: systemd-юниты, пользователи, права каталогов, TLS, backup/
   restore, `aer-admin health` на реальном сервере; Linux runtime новых изменений.
6. Чистая Windows VM / второй физический ПК; подпись пакета, SmartScreen.

## Аудит безопасности (раздел 13)

| Область | Вывод |
|---|---|
| TLS и pinning | Все соединения Viewer и Host к Gateway закреплены по SHA-256 (Dart `pinnedHttpClient`, Go `PinnedTLS`); CA не используется; без pin клиент не регистрируется |
| Первичное доверие | Явная сверка отпечатка пользователем или `connect.json` владельца с автоматической сверкой; остаточный риск TOFU при небрежной сверке — документирован |
| Владение ID | Номер выдаёт Core при регистрации по коду; привязан к учётке агента; перерегистрировать чужой номер нельзя; клон → `conflict` |
| Пароли | Сервер не видит пароль и не хранит верификатор; временный в памяти Host; постоянный — PBKDF2 600k; секреты не в логах (проверено) |
| Rate limiting | Core: 30 challenge/10 мин, 5 неверных viewer→устройство, 20 к устройству → блок 15 мин; Host: 5 → блок + смена пароля; Gateway: бан адреса, лимит регистраций |
| Авторизация сеанса | Сеанс только после `auth_ok` хоста **и** локального согласия; права = хост ∩ политика ∩ запрос; один сеанс на хост |
| Desktop/Input/Clipboard/Files | Проверяются Host-ом (native) независимо от Viewer; файлы выключены, пока не выбрана папка; «только просмотр» |
| Hijacking/Replay | Попытка и билеты привязаны к клиенту, одноразовые; шифротекст привязан к attempt/viewer/target/ключам; повтор на Host отвергается |
| Revocation | Отзыв устройства: агент + клиент + все сеансы; рантайм Host завершается; учётки дальше 401 (проверено сквозным тестом) |
| Файлы | Прежний pin-only TLS-канал, `os.Root`, атомарная публикация (без изменений) |
| Ошибки/логи | Ответы «нет кода/истёк/исчерпан» неразличимы; пароль/токены не логируются; Core аудит без содержимого |
| Секреты в Release | В ZIP нет токенов, ключей, тестовых фикстур; `connect.json` — только адрес и отпечаток |
| Потеря контроля Host | Закрытие приложения закрывает stdin → Host закрывает сеанс; потеря Core → Gateway рвёт туннели через 60 с; сроки сеанса на Host и в native |
| Listener | RDP/файлы только 127.0.0.1, порт выбирается при запуске; внешнего порта на клиенте нет |
| **Найдено и исправлено** | неограниченный рост счётчиков неудач в памяти Core (`c6d458b`); отправка повторно уже отвергнутого пароля из UI (`de27d90`/`6ecb71c`); регрессия сборки AER HOME из-за новой зависимости (`c8624a0`); ошибки в `aer-admin` (до коммита `4d921e2`) |
| Остаточные риски | Core — корень доверия (может подменить ключ Host); социальная инженерия через имя Viewer в диалоге (показываются имя **и** ID, текст предупреждения); устройство с правом регистрации видит имена устройств по номеру (перебор ограничен лимитами) |

Критических и высоких уязвимостей в реализованном коде после исправлений не
выявлено. **Публиковать Gateway в интернет — только после отдельного аудита
развёрнутой конфигурации** на сервере (`SERVER_UBUNTU.md`).

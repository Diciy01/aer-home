# Формат сцены v1

Источник истины — `contracts/scene.schema.json` (JSON Schema 2020-12). Пример и демо-планировка — `examples/home.scene.json` (тот же файл встроен в клиент: `apps/desktop/assets/scenes/demo_home.scene.json`, тест проверяет совпадение). Core проверяет документ в `core/internal/modules/scene/document.go`, клиент — в `apps/desktop/lib/src/scene/model/scene_codec.dart`; правила зеркальны.

## Принципы

- Сцена — **только визуальные данные**: комнаты, предметы, ассеты, положения, привязки. Никаких метрик, IP, токенов, исполняемых скриптов. Неизвестные поля отклоняются (так метрики не «протекут» в файл).
- Технические сведения живут в Registry. Сцена ссылается на них только через `entityBinding.entityId` (UUID сущности Registry). Привязка может указывать на удалённую сущность — объект остаётся в комнате и показывает «Объект Registry не найден».
- Формат не зависит от Flutter/Flame: геометрия ассетов (`footprint`, `height`) лежит в самой сцене, рисует её любой рендерер.

## Система координат

| | |
|---|---|
| Единица | **тайл** = 0,5 м. Высоты — в тех же тайлах. |
| Начало | `(0,0,0)` — дальний (верхний на экране) угол общей сетки дома, уровень пола. |
| Оси | `+x` — вправо-вниз на экране, `+y` — влево-вниз, `+z` — вверх. |
| Комната | `origin {x,y}` — её дальний угол на общей сетке; `size {w,d}` — размер по x и y. Комнаты не пересекаются. |
| Объект | `position {x,y,z}` — **локально в комнате**: минимальный угол повёрнутого основания; `z` — высота основания (стол — 0, монитор на столе — 1,5). Основание целиком внутри комнаты. |
| Поворот | `rotation` ∈ {0, 90, 180, 270}. «Лицо» ассета смотрит в `+y` при 0, `+x` при 90, `−y` при 180, `−x` при 270. При 90/270 ширина и глубина основания меняются местами. |
| Масштаб | `scale` ∈ [0,25; 4] — равномерно умножает `footprint` и `height`; положение не меняется (растёт от минимального угла). |
| Слой | `floor` (ковры: рисуются первыми; в просмотре не кликабельны, в редакторе выбираются), `object` (мебель, устройства), `wall` (на стене). |
| Оформление комнаты | `style.floor`, `style.wall` — **идентификаторы материалов из каталога** (`^[a-z][a-z0-9_]{0,31}$`, с контракта 0.5.0 вместо перечислений); необязательный `style.light` — пресет освещения (`warm`, `dim`, `cool`; отсутствие = дневной). Неизвестный клиенту материал рисуется нейтральным запасным. |
| Отделка предмета | `metadata.finish` — id отделки из каталога (`light`, `dark`, `sage`, `blue`; нет ключа = «как есть»). |

## Изометрическая проекция

2:1 диметрия («игровая изометрия», угол наклона рёбер ≈ 26,57°). Точка сцены в пиксели мира при масштабе 1:

```text
sx = (x − y) · 64 / 2
sy = (x + y) · 32 / 2 − z · 36
```

Обратное преобразование на плоскости высоты `z`: `a = sx/32`, `b = (sy + 36z)/16`, `x = (a+b)/2`, `y = (b−a)/2`. Реализация и тесты: `lib/src/scene/geometry/iso.dart`, `test/scene/geometry_test.dart`.

Камера: `экран = (мир − центр) · zoom + центр_окна`. Масштаб ограничен [0,6 × «весь дом»; 3,5], центр камеры не может покинуть границы дома — сцену нельзя «потерять».

## Порядок отрисовки

1. Тень дома, полы комнат (по возрастанию `x0+y0`), слой `floor`, контактные тени, пятна света ламп.
2. Стены и объекты — **топологическая сортировка** параллелепипедов: A рисуется раньше B, если на первой разделяющей оси (x, затем y, затем z) A дальше от зрителя; если объёмы пересекаются — контейнер (полка, стойка) раньше содержимого. Рёбра строятся только для пар с перекрывающимися проекциями; гипотетические циклы разрываются по ключу глубины.
3. Подсветка наведения/выбора, значки состояний и названия комнат — поверх, в экранных координатах (размер не зависит от масштаба).

Выбор объекта идёт в обратном порядке отрисовки по выпуклому силуэту (шестиугольник проекции): кликается видимый объект, а не скрытый за ним; высокие стены перекрывают то, что за ними.

## Стены

Строятся рендерером, а не хранятся: на дальних сторонах комнаты (`north` — y = y0, `west` — x = x0). Внешние стены высотой `wallHeight` с окнами, перегородки между комнатами — низкие (cutaway-вид) с дверным проёмом. Ближние стены не рисуются.

## Состояния

`visualState` хранит **только явно тестовые** состояния (`{"demo": "online"}`) и допустим лишь при `"demo": true` и без `entityBinding`. Реальные состояния с M05 приходят из Monitoring во время работы (через `LiveStatus` в Scene Binding) и в файл не пишутся. Без данных мониторинга привязанный объект показывает `unknown`, архивный в Registry — `archived`, при загрузке — `loading`; `online` выдаётся только по реальным данным Monitoring, устаревшие данные помечаются бледным значком.

## Тип размещения (редактор M04)
Тип размещения — свойство ассета в каталоге клиента (`scene/catalog/scene_catalog_data.dart`), в документ не пишется (документ хранит только `layer` и `position.z`):

| Тип | Слой | Где может стоять | Пересечения |
|---|---|---|---|
| `floor` | object | только `z = 0` | запрещены с объектами `floor/surface` |
| `surface` | object | на полу, на крышке предмета с `top` (z = верх опоры, центр над опорой, ≥60 % площади) или на полке (`shelves`) внутри контейнера | как `floor`; содержимое полки не конфликтует с контейнером |
| `wall` | wall | на внешней задней стене: север (`rotation 0`, `y ≤ 0,35`) или запад (`rotation 90`, `x ≤ 0,35`), верх не выше `wallHeight` | только с другими `wall` |
| `overlay` | floor | `z = 0` | ни с чем (ковёр под мебелью) |

## Версионирование и хранение

- `schemaVersion` = 1. Новая версия = миграция `N → N+1` в Core (`upgraders`) и в клиенте, затем повышение версии; старые документы поднимаются при чтении.
- **Core (канон):** `scene_documents` (документ, `revision`, оптимистическая блокировка) + `scene_document_history` (20 прошлых ревизий для восстановления/undo в M04). Неудачная проверка не трогает сохранённые данные.
- **Клиент (черновик редактора, M04):** `scene-draft.json` в том же каталоге — рабочая копия с ревизией начала правок; атомарная запись; повреждённые файлы откладываются как `.corrupt-<время>`, хранится не более 3 (то же для кэша).
- **Клиент (кэш):** `~/.local/share/aer-home/desktop/scene-cache.json` (`AER_DESKTOP_DATA_DIR` переопределяет) — последняя сцена + снимки привязанных сущностей (имя, тип, возможности с подписями) для офлайн-просмотра. Запись атомарная; повреждённый файл откладывается как `.corrupt-<время>`.
- **Только клиент, не канон:** положение камеры, выбор, открытые панели.
- Демо-планировка не сохраняется в Core без явного нажатия «Сохранить в Core».

## Правила проверки (кратко)

UUID в нижнем регистре для `sceneId`, комнат, объектов и привязок; уникальность id; ссылки `roomId`/`assetId` существуют; комнаты не пересекаются; объект внутри комнаты; диапазоны: координаты комнат ±500, размеры 1…200, высота ассета до 40, масштаб 0,25…4; `metadata` — до 16 строк по 512 символов. Полный список — `scene.schema.json` и тесты `TestValidationRules` / `validation mirrors Core rules`.

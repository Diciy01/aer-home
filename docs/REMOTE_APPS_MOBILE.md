# Remote Apps для iOS/Android — спецификация (M07.6)

**Статус: UNSUPPORTED на текущем транспорте; архитектура и API подготовлены.** Мобильные приложения — этапы M11/M12.

## Почему не сейчас
| Требование | GNOME Wayland | Windows | Итог |
|---|---|---|---|
| Список окон приложений | нет публичного API (Shell Introspect закрыт) | `EnumWindows` (UNVERIFIED) | на GNOME — только диалог портала |
| Захват одного окна | портал ScreenCast «окно» (интерфейс есть, PARTIALLY) — диалог на каждый сеанс | Windows Graphics Capture (UNVERIFIED) | возможно, но не через RDP |
| Ввод только в это окно | портал RemoteDesktop вводит **глобально** | SendInput — глобально | **изоляции нет** |
| RDP RemoteApp | не поддерживается gnome-remote-desktop | только серверные редакции/RDS | нет |
Поэтому показывать «одно приложение» поверх полного рабочего стола было бы ложной изоляцией — запрещено требованиями.

## API (уже есть)
`GET /remote/hosts/{id}/apps` → `{status: "unsupported"|"available", reason, apps:[{id,title}]}`. `POST /remote/sessions {kind:"app"}` → 422 `UNSUPPORTED` (`reason: apps_unsupported`). Возможность хоста `capabilities.apps` объявляет только бэкенд, умеющий изоляцию.

## Будущий протокол (предложение)
1. Хост-агент с бэкендом `app-stream`: список разрешённых владельцем приложений (allowlist в конфиге агента, не из запроса).
2. `POST /remote/sessions {kind:"app", appId}` → агент открывает захват окна (Wayland: портал с диалогом у пользователя хоста; Windows: Graphics Capture) и WebRTC-поток (DTLS-SRTP) напрямую к телефону; сигнализация — через Core (SDP/ICE как события сеанса).
3. Ввод: события касаний в **координатах окна**; агент отбрасывает всё вне окна и переводит фокус только на него; системные диалоги поверх окна → поток паузится (`WINDOW_NOT_CAPTURABLE`).
4. При сворачивании/закрытии окна → `WINDOW_NOT_CAPTURABLE`, без переключения на рабочий стол.

## Сенсорное управление (спецификация UI)
Тап = клик; долгое нажатие = правый клик; два пальца — прокрутка; щипок — масштаб изображения (не окна); экранная клавиатура по кнопке; вставка из буфера — только явной кнопкой; кнопка «Завершить» всегда видна.

## Ограничения платформ
- iOS: фоновая работа ограничена — сеанс завершается при уходе приложения в фон; WebRTC — нативный фреймворк.
- Android: аппаратный декодер, ориентация; проверять на реальном устройстве (у владельца есть Samsung — использовать на M12).

## Тестовые контракты
Контрактные тесты Core уже проверяют `RemoteApps` и отказ `kind=app`; при появлении бэкенда добавить: allowlist, ввод вне окна отбрасывается, сворачивание → ошибка, без fallback на рабочий стол.

# Подключение удалённого доступа (M07)

Удалённое **управление** компьютером: рабочий стол, мышь, клавиатура, текстовый буфер обмена, файлы — как TeamViewer/RustDesk, но без чужого облака. Изображение открывается во внешнем RDP-клиенте (Remmina на Linux, «Подключение к удалённому рабочему столу» на Windows), который запускает AER.

## 1. Компьютер, к которому подключаются (хост Ubuntu GNOME)
Требования: Ubuntu 24.04+ GNOME (Wayland или X11), пакет `gnome-remote-desktop` (есть по умолчанию), вход пользователя выполнен (экран блокировки AER не обходит).
1. В AER: «Устройства» → компьютер (тип «Компьютер», возможность «Удалённый рабочий стол» включена по умолчанию).
2. «Мониторинг → Агенты и интеграции → Добавить», вид **remote** (или `POST /api/v1/monitoring/agents {"entityId":…,"name":"remote","kind":"remote"}`). Токен — в файл с правами 600, например `~/.config/aer-home/remote-host.token`.
3. Скопируйте `deploy/remote-host.example.json` в `~/.config/aer-home/remote-host.json`, укажите `coreUrl`, `address` (по какому имени/IP клиент достанет этот ПК — LAN или Tailscale), папку обмена `files.dir`. `approval: "prompt"` — спрашивать вас на этом ПК при каждом подключении.
4. Соберите и запустите агент **в вашем сеансе** (не от root):
   ```bash
   cd core && go build -o bin/aer-remote-host ./cmd/aer-remote-host
   bin/aer-remote-host -config ~/.config/aer-home/remote-host.json
   ```
   Автозапуск при входе — по желанию, вручную (например, `~/.config/autostart`). AER ничего не устанавливает сам.

Агент забирает настройку RDP GNOME на себя: держит его **выключенным**, включает на время одобренного сеанса с новым паролем и запускает демон gnome-remote-desktop только на этот сеанс. Если вы пользовались «Настройки → Общий доступ → Удалённый рабочий стол» вручную — после агента настройте его заново (или не запускайте агент).

## 2. Компьютер, с которого подключаются
- **Ubuntu**: AER HOME + Remmina (`remmina`, `remmina-plugin-rdp`; в Ubuntu обычно уже есть). AER записывает сертификат хоста в `~/.config/freerdp/server/` (закрепление) и запускает Remmina.
- **Windows**: AER HOME; клиент — встроенный `mstsc` (UNVERIFIED).

## 3. Дома (одна сеть)
Ничего дополнительно: «Удалённый доступ» → компьютер → «Подключиться».

## 4. С работы / из другого места
С M14 (ADR-017) — **через собственный AER Remote Gateway** на домашнем сервере, без Tailscale и чужих серверов: один порт (WAN 443 → сервер:8443), сопряжение клиента одноразовым кодом, закреплённый сертификат, ретрансляция через Gateway. Порядок развёртывания и что проверено — `docs/REMOTE_GATEWAY.md`. Токен владельца и API Core на рабочий ПК **не** переносятся; рабочему ПК выдаётся отдельная отзываемая учётка клиента с доступом только к выбранным компьютерам.

Статус: Gateway и движок проверены на изолированном стенде (loopback); через интернет и с настоящим RDP через ретрансляцию — UNVERIFIED; клиент AER Connect для Windows — после M10 (M14.4). Прежний вариант M07 через Tailscale/WireGuard больше не рекомендуется.

## 5. Хост Windows
Нужна Windows Pro/Enterprise: «Параметры → Система → Удалённый рабочий стол» включает пользователь. Агент с `"backend": "windows-rdp"` только сообщает готовность; вход — вашей учётной записью Windows. Проверка — `REMOTE_WINDOWS_VALIDATION.md` (UNVERIFIED).

## Проблемы
| Симптом | Что проверить |
|---|---|
| «Агент удалённого доступа не на связи» | агент запущен в сеансе пользователя? `coreUrl` доступен? токен не отозван? |
| «Хост не готов: gnome-remote-desktop недоступен» | пакет установлен, агент запущен не от root и в графическом сеансе |
| Remmina просит пароль / «authentication failure» | версия агента ≥ 0.1.0 (пароль 30 символов); старые сеансы закрыты |
| «REMOTE HOST IDENTIFICATION HAS CHANGED» | сертификат хоста изменился (переустановка агента?) — сверьте отпечаток в карточке; при подмене — не подключайтесь |
| Чёрный экран / экран блокировки | ПК заблокирован — разблокируйте паролем в окне клиента |

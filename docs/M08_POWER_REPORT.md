## Что проверено только автоматическими тестами (SIMULATED)
Go — модуль `power` (23 теста), агент `powerhost` (12), контракт (1, включая доставку настоящего Magic Packet на приёмник 127.0.0.1 через HTTP API):
Magic Packet (102 байта, 16 повторов), разбор/нормализация MAC (форматы, групповой, нулевой, мусор, попытка внедрения), адрес назначения (частные сети/loopback/255.255.255.255; интернет и IPv6 — отказ), выбор интерфейса (несуществующий — отказ), тайм-аут WoL + инцидент, устройство уже включено, ошибка отправки, отправка выключена в конфиге, один ПК с Core; выключение (успех по молчанию ≥45 с, «продолжает отвечать» → тайм-аут), перезагрузка (тот же `bootId` не считается, новый — успех, нет повтора), смена ОС (успех, загрузилась другая ОС → ошибка, цель недоступна/неоднозначна, BitLocker блокирует до разрешения, нет помощника sudo), подтверждение (одноразовое, привязано к действию/устройству/цели, истекает), Idempotency-Key (повтор, другая операция → 409, 8 параллельных запросов с одним ключом → одно задание), отмена (до выдачи — да, после — 409, гонка отмена↔выдача исключена условным UPDATE), отзыв разрешения политикой отменяет неотданные задания, тайм-аут выдачи, перезапуск Core (неотданные → failed, не пересылаются), ошибка агента → инцидент, режим проверки → simulated, чужой агент не видит задания, валидация hello (внедрение в id записи, лишние ключи), одно задание на устройство и общий лимит, хранение истории; агент: разбор efibootmgr/lsblk/logind/bcdedit (en/ru)/manage-bde/sudo-листинга (кеш пароля не считается), фиксированные argv Linux/Windows, отказ планировать запись не из инвентаризации, сквозной цикл с настоящим Core и поддельной системой (режим проверки → simulated; режим исполнения → BootNext + reboot вызваны подделкой, агент перестал опрашивать; BootNext не подтверждён → перезагрузки нет), повтор/истёкшая команда отклоняются, отзыв учётки останавливает агента, без Core агент ничего не делает.
Flutter (11 новых, всего 187): токен подтверждения + новый Idempotency-Key, слежение за заданием, проверка без подтверждения, без Core данные устаревают и команды недоступны; карточки (недоступные действия видны, неактивны, с причиной), выключение с двойным подтверждением, отмена в очереди, смена ОС (текущая ОС не предлагается), диалог WoL (выключенная отправка объяснена, ошибка MAC показана, широковещательный адрес подставлен по интерфейсу), политика (смена ОС — явно), история, переход в Remote, панель в доме.

## Не подтверждено (UNVERIFIED)
- Реальные выключение, перезагрузка, сон через logind (в т.ч. из фонового сеанса — polkit может потребовать пароль).
- Реальная запись BootNext и загрузка Windows/Ubuntu по ней на этой прошивке; переход Windows → Ubuntu.
- Wake-on-LAN из S5/S3 (UEFI, драйверы обеих ОС), доставка по реальной LAN, выбор интерфейса на сервере.
- Агент на Windows (собирается, разбор покрыт тестами; права администратора, локализованный вывод `bcdedit`/`manage-bde`).
- Поведение при реально включённом BitLocker.
- Работа на отдельном слабом сервере (замеры — на этом ПК; оценка ниже).

## Безопасность (проверено тестами)
Закрытый список действий; клиент не передаёт команд (лишние поля → 400); агент принимает только записи из своей инвентаризации; фиксированные argv; `sudo -n` только для одного бинарника, правило не устанавливается AER; подтверждение одноразовое + Idempotency-Key + аудит каждого запроса, включая отказы; отдельная отзываемая учётка агента на каждую ОС; таймауты на каждом этапе; без автоматических повторов; режим проверки по умолчанию; WoL только в домашние диапазоны, выключен по умолчанию; секретов в БД нет (токены агентов — хэши в Monitoring).
**Права агента**: с `"execute": true` агент действует с правами пользователя, под которым запущен, поэтому у этого пользователя не должно быть широких прав sudo без пароля — только узкое правило для `efibootmgr --bootnext` (пример — `POWER_CONNECT.md`). Состояние sudoers основного ПК зафиксировано в локальных заметках, AER его не меняет.

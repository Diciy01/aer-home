# Подключение ботов и автоматизаций (M06)

Общий принцип: **наблюдать** можно любого бота без доступа к нему — достаточно heartbeat. **Управлять** — только через адаптер, который владелец объявил в конфигурации Core (`bots` в JSON-конфиге, пример — `deploy/core-bots.example.json`). Из интерфейса нельзя задать команду, путь или URL для исполнения. AER HOME ничего не устанавливает (Docker, n8n, службы) и не меняет права.

После изменения конфигурации перезапустите Core. Ошибка в разделе `bots` остановит запуск с понятным сообщением.

## 1. Telegram-бот (любой язык)
1. «Боты → Добавить бота»: тип «Telegram-бот», имя, категория, сервер; оставьте «Выдать токен heartbeat».
2. Сохраните показанный **один раз** токен в файл рядом с ботом: `install -m 600 /dev/null ~/.config/aer/my-bot.token` и вставьте токен.
3. В коде бота (Python, только стандартная библиотека — `tools/bot-heartbeat/aer_heartbeat.py`):
   ```python
   from aer_heartbeat import Heartbeat
   hb = Heartbeat("http://<адрес Core>:8787", token_file="/home/user/.config/aer/my-bot.token",
                  version="1.4.2", interval=15)
   hb.start()
   # после реального успешного действия:           hb.success()
   # после ошибки (текст очищается Core от секретов): hb.error("Telegram API: 502")
   # результат своей проверки API Telegram:          hb.api_ok(False)
   job = hb.job_started("Ежедневная рассылка")   # задания (необязательно)
   hb.job_finished(job, ok=True, result="отправлено 12")
   ```
   Другой язык: `POST /api/v1/monitoring/agent/report` (heartbeat, `bot.version`, ошибки) и `POST /api/v1/bots/agent/jobs` с заголовком `Authorization: Bearer <токен бота>` — формат в `contracts/openapi.yaml`.
4. **Токен Telegram не нужен** ни для мониторинга, ни для ошибок API, ни для заданий. Только если нужна проверка `getMe` из AER HOME: положите токен Telegram в файл с правами 600 на сервере Core и объявите его:
   ```json
   "bots": { "telegramTokens": [ { "id": "my-bot", "file": "/etc/aer-home/my-bot.token" } ] }
   ```
   затем выберите «Файл токена "my-bot"» в мастере. Токен не попадает в Registry, интерфейс, логи и ответы API.
5. Привязка к процессу или контейнеру: если бот запущен Core — выберите адаптер `process`; если в Docker — укажите имя контейнера (шаг «Где работает») и/или адаптер `docker`.

Проверка: в карточке «Heartbeat: N с назад», состояние «В сети». Нет heartbeat дольше тайм-аута → «Недоступен» и инцидент; бот вернулся → инцидент закрывается сам.

## 2. Python-процесс под управлением Core
```json
"bots": { "controllers": [ {
  "id": "report-bot", "label": "Бот отчётов", "kind": "process",
  "command": ["/usr/bin/python3", "-u", "/opt/bots/report/bot.py"],
  "workDir": "/opt/bots/report", "env": ["LANG=C.UTF-8"],
  "stopTimeoutSec": 10, "allow": ["start", "stop", "restart"] } ] }
```
- `command` — argv без оболочки, первый элемент — абсолютный путь. `env` — без секретов (переменные с TOKEN/SECRET/PASSWORD/API_KEY отклоняются): бот читает свой токен из своего файла.
- Core запускает процесс в своей группе, собирает его stdout/stderr в журнал бота, меряет CPU/RAM, фиксирует код выхода. Самостоятельное завершение → событие «упал» и инцидент.
- Остановка: SIGTERM, через `stopTimeoutSec` — SIGKILL. При остановке Core его процессы останавливаются; **после запуска Core процессы нужно запустить** (кнопкой или API) — Core не стартует ботов сам.
- Уже работающий вне Core процесс Core не трогает и не «усыновляет»; для таких ботов используйте heartbeat (+ systemd/Docker адаптер).
- Пример тестового бота без Telegram: `tools/bot-heartbeat/example_bot.py`.

## 3. Пользовательская служба systemd
```json
{ "id": "news-bot-unit", "kind": "systemd_user", "unit": "news-bot.service", "allow": ["restart"] }
```
Работает только с `systemctl --user` того пользователя, от имени которого запущен Core (нужны `XDG_RUNTIME_DIR`/сессионная шина). Системные юниты не поддерживаются намеренно. Состояние берётся из `systemctl --user show`.

## 4. Docker
- Мониторинг: укажите имя контейнера в мастере (поле «Docker-контейнер») или выберите тип объекта «Docker-контейнер» — состояние, CPU/RAM, последние ошибки stderr берёт Monitoring (только чтение).
- Управление: объявите контейнер
  ```json
  { "id": "shop-bot-container", "kind": "docker", "container": "shop-bot", "allow": ["restart"] }
  ```
  Используется локальный сокет `bots.dockerSocket` (по умолчанию `/var/run/docker.sock`; TCP не поддерживается). Пользователю Core нужен доступ к сокету (группа `docker`) — AER HOME права не меняет. Без Docker карточка показывает причину («сокет не найден», «нет прав»), кнопки управления не выполняются.

## 5. n8n
1. В n8n: Settings → n8n API → создать ключ. Сохраните его в файл с правами 600 на сервере Core.
2. Объявите экземпляр:
   ```json
   "n8n": [ { "id": "home", "label": "n8n дома", "baseUrl": "http://127.0.0.1:5678",
              "apiKeyFile": "/etc/aer-home/n8n.key", "allowRetry": false } ]
   ```
3. «Добавить бота» → тип «Автоматизация» → шаг «Мониторинг» → n8n «home»; при желании — ID нужных workflows через запятую (пусто — все).

Что видно: состояние сервиса (`/healthz`), список workflows (только просмотр), последние 50 выполнений каждого отслеживаемого workflow как задания (длительность, статус, ошибки), инцидент при новом неудачном выполнении. **Workflows не изменяются и не запускаются.** Повтор неудачного выполнения — только при `allowRetry: true` и после подтверждения. Если n8n недоступен или ключ отклонён — причина в карточке и в «Мониторинг → Агенты и интеграции».

## 6. Произвольное приложение с heartbeat
Тип «Приложение», «Процесс» или «Служба» + токен heartbeat. Любой язык, два HTTP-запроса (см. п. 1.3). Состояние — по heartbeat; если у приложения есть HTTP-проверка — `attributes.monitoring.url` объекта Registry.

## Безопасность
- Токены и ключи — только в файлах на сервере (права 600), никогда в Registry, интерфейсе, URL-логах. Перед записью в журнал текст очищается от токенов Telegram, `Bearer`, `password=…` и т. п.
- Каждое действие требует одноразового подтверждения, выполняется один раз на ключ идемпотентности и попадает в журнал аудита.
- Список разрешённых действий задаётся на адаптере (`allow`); бот без адаптера — «только мониторинг», кнопки неактивны.

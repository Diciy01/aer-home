# M07 Remote Desktop + S-Remote — отчёт

Дата: 2026-10-27. Машина: Ubuntu 24.04.5 LTS, GNOME 46 (Wayland), RX 570, 12 потоков. Windows-машин, второго ПК и мобильных устройств в испытаниях не было. Все хосты и клиенты проверок — **тестовые** (изолированный стенд `tools/remote-lab`), сеанс и настройки пользователя не затрагивались.

## Что подтверждено реальными испытаниями (стенд, localhost)
Хост: отдельный headless-сеанс GNOME Shell 46 (Wayland, mutter) со своей D-Bus и своими настройками + gnome-remote-desktop 46.3, которым управляет `aer-remote-host`. Клиент: Remmina 1.4.43 / FreeRDP 3.32 в изолированном Xvfb, **запущенная из приложения AER HOME**. Core — настоящий `aer-core` (изолированный каталог данных).

## Что проверено только автоматическими тестами
Go (`internal/modules/remote`, `internal/remotehost`, контракт): готовность хоста (агент молчит, учётка отозвана, нет возможности в Registry, Monitoring offline), политика и её выключение (отзыв), тайм-ауты (ответ хоста, подтверждение, выдача, переподключение, срок), идемпотентность, 1 сеанс на хост при 8 параллельных запросах, общий лимит, чужой агент не видит и не меняет сеансы, пароль/токен не попадают в БД и WAL, сквозной цикл Core + агент с подставным `grdctl` (пароль в `grdctl` = выданному, отзыв → демон остановлен, отзыв учётки → агент останавливается), локальное истечение без Core, канал файлов (обход путей, лимит, сумма). Flutter: путь подключения, отказ на хосте, нет клиента, переподключение без второй выдачи, отзыв стирает данные, устаревшие данные, кнопки по готовности, политика, закрепление для Remmina, панель в доме.

## Не подтверждено
Windows-хост и клиент `mstsc` (план — `REMOTE_WINDOWS_VALIDATION.md`); подключение между двумя реальными ПК по LAN и через Tailscale; живой сеанс вошедшего пользователя (проверен headless-сеанс GNOME того же mutter); подтверждение `approval=prompt` вживую (только фейк); несколько мониторов; кириллица; задержка клавиатуры (на стенде — аномалия xdotool/Xvfb).

## Технически недоступно
Изоляция одного приложения (Remote Apps) на GNOME Wayland и на RDP; список окон GNOME без расширений; запрет буфера обмена со стороны сервера GNOME; отзыв активного RDP-сеанса Windows из агента (без WTS API).

## Производительность (стенд, localhost)
| Метрика | Значение |
|---|---|
| Запрос сеанса → хост готов (RDP включён, демон запущен) | 139–143 мс |
| Запуск клиента → соединение у агента | 865–962 мс |
| Запуск клиента → первый кадр | ≈980 мс |
| Мышь → изменение изображения | p50 44 мс, p95 63 мс |
| Клавиша → изображение | 20–950 мс (аномалия стенда, не транспорт; перемерить с реальной клавиатурой) |
| Отзыв/завершение → порт закрыт | 95–99 мс |
| `kill -9` клиента → `reconnecting` | 0,6 с |
| CPU / RSS при подключённом сеансе (простой рабочий стол, 30 с) | aer-core 0,20 % / 23 МБ; aer-remote-host 0,47 % / 15 МБ; Remmina 0,10 % / 144 МБ |
| CPU при активном вводе (24 с) | gnome-remote-desktop 3,4 % (RSS 107 МБ), gnome-shell хоста 13,1 %, Remmina 2,1 % |
| Трафик | ≈0,37 МБ за 30 с подключения (статичный экран); ≈1,5 МБ за сеанс тестов ввода |
| Кодек | RDPGFX без H.264 (сборка Remmina), программный; Core видео не обрабатывает |
Разрешение на стенде задаёт клиент (виртуальный монитор headless-сеанса); изменение размера/масштаб — средствами Remmina.

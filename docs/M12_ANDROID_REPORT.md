# M12 Android — отчёт

Дата: 2026-10-28. Машина: та же, что в M07–M09 (Ubuntu 24.04, x86_64, KVM). Серверная часть не менялась: контракт 0.10.0, новых маршрутов нет. Проверки шли против **изолированного тестового Core** (стенд `tools/network-lab` + сцена `tools/mobile-lab`, только 127.0.0.1); реальный домашний Core и реальные устройства в M12 не трогались.

## Архитектура
`apps/android`: `:core-api` (чистый Kotlin — клиент API, снимок, протокол действий), `:scene` (чистый Kotlin — перенос геометрии сцены desktop, тот же формат v1), `:app` (Compose). Источник истины — Core (Registry, Monitoring, Network, Power, Bots, Scenes); на телефоне — только адрес, режим, зашифрованный токен и кэш последней сцены. Решения — ADR-016, описание — `ANDROID.md`.

## Реализовано
- Два режима с выбором при первом запуске и переключением без потери данных и настроек: «Дом» (изометрический дом из сцены Core) и «Классика» (Обзор, Устройства, Журнал, Сеть, Ещё).
- Обзор: устройства по состояниям, открытые/критичные инциденты, «требуют внимания», сводка сети, питание и боты, источники данных Monitoring, время обновления.
- Устройства: поиск, фильтры, проблемные первыми; карточка — Registry, состояние Monitoring (задержка, последний ответ/проверка), сетевая строка M09, питание с действиями, переход к боту, инциденты и журнал устройства, «Показать в доме».
- Журнал: активные и закрытые инциденты, журнал с фильтром уровня и подгрузкой по курсору; инцидент — хронология, причина только если её дал Core, «Подтвердить», переход к устройству.
- Сеть и ТВ (M09): сводка, интернет, роутеры и WAN, телевизоры, Sunshine отдельно от ПК и ТВ, прочие устройства, инциденты, журнал проверок, «Проверить сейчас» (409 → понятное сообщение), «Открыть Sunshine» только для http(s).
- Питание: действия ровно как их отдаёт Core (недоступные — с причиной), смена ОС с выбором цели, подтверждение со сводкой/проверками/рисками, отслеживание задания до итога, SIMULATED явно отличается от выполнения.
- Боты: список, карточка, разрешённые действия через подтверждение Core, журнал.
- «Дом»: комнаты, стены с окнами, предметы, освещение и отделки из каталога, значки реальных состояний привязанных устройств (устаревшие — бледные, демо — с отметкой), выбор касанием и списком предметов комнаты, «Подробнее» → карточка устройства, масштаб/сдвиг с ограничениями desktop, фокус на комнате; сцена из Core / последняя полученная / демо — всегда подписано.
- Подключение: адрес с проверкой (http на публичный адрес запрещён, для LAN — предупреждение), токен в Keystore, «Проверить» различает «Core недоступен» и «токен отклонён», «Удалить токен».
- Ошибки: баннер связи (не настроен / нет связи + возраст данных / токен отклонён / не AER Core / устарело), раздельные ошибки разделов, понятные русские причины сетевых сбоев, сохранение последних данных при сбое.

## Что проверено только тестами (JVM)
- `:core-api` — 31 тест: конверт и коды ошибок, публичный `/health`, отсутствие токена до запроса, не-JSON ответ, закрытый порт, базовый путь и кодирование, **разбор реальных ответов Core** (фикстуры стенда: сеть, питание, Monitoring, Registry, логи), постраничный Registry; снимок — не настроен, полная загрузка, сбой Core с сохранением данных и устареванием, отклонённый токен, чужой сервис, ошибка одного раздела, выключенные модули, однократная загрузка типов; протокол действий — токен и ключ, SIMULATED, `check` без подтверждения, отказ Core с причиной, потерянный ответ → повтор с тем же ключом; проверка адресов.
- `:scene` — 21 тест: проекция и обратная проекция, силуэты, порядок (зеркало desktop `geometry_test`), демо-планировка (порядок, выбор, ковры, границы, предметы комнаты), формат и версия, привязки (декор, демо, нет данных Monitoring ≠ «в сети», устаревание, удалённая/архивная/недоступная привязка), камера.
- `:app` — 8 тестов состояния интерфейса (`AppViewModel`): первый запуск, сохранение режима, переключение без потери данных, стек навигации, «Показать в доме», проверка адреса/токена, недоступный Core, удаление токена.

## Ограничения и UNVERIFIED
- Физическое Android-устройство — UNVERIFIED (только эмулятор API 35). Реальный Core в LAN/Tailscale (режим `local`/`server`) — UNVERIFIED: в M12 только стенд.
- Телефон хранит **токен владельца** (полные права); device-scoped учётки и отзыв — ADR-007 «Отложено», нужны до доступа вне доверенной сети.
- Сцена на телефоне — только просмотр/навигация/выбор; редактирование не реализовано. Рисунки предметов упрощены (параллелепипеды), геометрия и порядок — как в desktop.
- Действия питания на стенде — только `check` (агента нет); подтверждение и выполнение опасных действий проверены JVM-тестами против фейкового Core, не на реальном агенте.
- Боты на стенде отсутствуют: экран ботов на эмуляторе показан только пустым; действия ботов — JVM-тесты.
- Remote Desktop/Remote Apps на телефоне — UNSUPPORTED (как в M07).
- Release подписан debug-ключом — тестовая сборка, не для распространения.
- Сквозные тесты на release требуют дополнительных keep-правил AndroidX только для тестового прогона (код приложения, kotlinx.serialization и OkHttp при этом минифицированы как обычно). Обычный release без этих правил на эмуляторе проверен вручную только частично: запуск, выбор «Классика», экран подключения; работа с данными в нём — UNVERIFIED.

# Безопасность AER Remote (M07)

| Мера | Как реализовано | Проверено |
|---|---|---|
| Отдельная идентификация устройства | у каждого хоста своя учётка агента Monitoring `kind=remote` (`aer1.<id>.<secret>`, в Core только SHA-256); маршруты агента не принимают токен владельца, маршруты владельца — токен агента; агент ОС (`kind=host`) не может говорить за удалённый доступ | Go: контракт, e2e |
| Нет «одного ключа ко всем ПК» | токен владельца создаёт **запрос** сеанса; доступ к рабочему столу даёт только одноразовый пароль, который хост генерирует на этот сеанс | Go, стенд |
| Короткоживущие разрешения | пароль RDP — 30 случайных символов на сеанс; выдача клиенту **один раз** в течение 60 с; после выдачи стирается из памяти Core; в БД и аудите не хранится (тест читает файл БД и WAL) | Go |
| Ротация действительно работает | демон gnome-remote-desktop запускается агентом на сеанс и останавливается после: работающий демон держит старый пароль (найдено на стенде) | стенд |
| Порт закрыт вне сеанса | RDP и канал файлов слушают только во время сеанса; при завершении/отзыве порт закрывается за ≈100 мс | стенд |
| Подлинность хоста | сертификат хоста приходит от агента через Core; клиент кладёт его в хранилище FreeRDP; файлы — HTTPS с проверкой SHA-256 сертификата | стенд (подмена → отказ TLS) |
| Подтверждение на компьютере | `approval: prompt` — вопрос пользователю хоста (zenity), отказ → `failed` | Go (фейк), живьём UNVERIFIED |
| Отзыв | `/revoke`, `/revoke-sessions`, выключение политики; отзыв учётки агента — агент останавливается и оставляет RDP выключенным | Go e2e, стенд |
| Тайм-ауты и лимиты | ответ хоста, подтверждение, выдача, переподключение, срок сеанса; 1 сеанс на хост, общий лимит | Go |
| Без Core | сеанс RDP продолжается, агент закрывает его по `expiresAt`; отзыв требует связи агента с Core | стенд |
| Аудит | события сеанса (`remote_events`) + Monitoring; без содержимого экрана, нажатий, буфера и файлов | Go |
| Сеть | только LAN/VPN (Tailscale/WireGuard); порты в интернет не публикуются; AER не меняет брандмауэр и VPN | документация |

## Известные ограничения
- Пароль сеанса на доли секунды виден в argv `grdctl` и всё время сеанса — в argv клиента Remmina (`rdp://user:pass@…`) — процессам того же пользователя.
- Пароль сеанса и токен файлов проходят через Core: Core↔агент и Core↔клиент должны идти по loopback или VPN. По открытому HTTP в LAN их можно подслушать (короткоживущие, одноразовые). TLS для Core — следующий шаг.
- «Подключён» = TCP-соединение с портом RDP; неудачная попытка входа даёт короткое «подключён → прервано».
- Выключение буфера обмена на сеанс — только в клиенте (сервер GNOME не умеет запрещать CLIPRDR).
- RDP показывает **весь** рабочий стол сеанса пользователя; экран блокировки не обходится.
- Windows-хост использует учётную запись Windows (AER её не меняет) — одноразового пароля нет.

# Модель угроз и правила безопасности

## Активы
Устройства дома, экран ПК, доступ к файлам, токены Telegram, SSH ключи, конфигурации VPN/роутера, журналы, персональная информация, управление загрузкой и питанием.

## Доступ
- Самостоятельный self-hosted, но единая учётка/устройства требуют authentication.
- Внешний доступ только через приватную защищённую overlay-сеть (например Tailscale) или эквивалент; **не** открывать Core, RDP, Sunshine, SSH, Docker socket и debug endpoints в WAN.
- Сеансы удалёнки с короткоживущими токенами, транспортным шифрованием, explicit revoke, журналом подключений.
- Особо опасные операции (power, OS switch, bot restart, Docker stop, file delete): double confirmation + audit.
- Агенты least privilege. Привилегированный helper только с allowlist операций, не произвольный shell.

## Устройства
- Мобильный клиент не должен получать full desktop даже по скрытому URL/API: проверка server-side клиентских scopes и разрешений. Не полагаться только на идентификатор платформы; нужны credentials с назначенными capabilities.
- Отдельное окно должно быть действительно изолировано, без захвата уведомлений, всплывающих окон и соседних процессов; если нельзя гарантировать, feature disabled.
- Скрывать конфиденциальное содержимое в preview/уведомлениях; требовать Face ID/биометрию только как локальный дополнительный барьер при доступности.

## Секреты
Environment/OS keychain/secret store, токены не в YAML/SQLite plain/scene exports и git. Скриншоты, exports и логи проходят redaction. Примерные ключи в тестах — явно фиктивные.

## Работа Claude
Любой live change сетевых параметров, загрузчика, дисков, firewall, OS reboot или docker service restart требует разрешения; по умолчанию READ-ONLY на существующей системе. Тесты используют mocks и staging.

## Recovery
Backup + restore проверять; stateful schema migration с откатом, оговорить невозможность гарантированного rollback прошивки/UEFI. Операции reboot не повторяются автоматически. Соединение умерло — показать pending/unknown, не success.

## Удалённый доступ (M07)
Отдельная учётка агента на каждый хост, пароль RDP на один сеанс с однократной выдачей, RDP открыт только во время сеанса, закрепление сертификата хоста, отзыв, сроки, аудит без содержимого; только LAN/VPN. Подробно — `docs/REMOTE_SECURITY.md`.

## Питание и смена ОС (M08)
Закрытый список действий без текста команд от клиента; агент исполняет фиксированные argv и только загрузочные записи из своей инвентаризации; режим проверки по умолчанию; `sudo -n` для одного бинарника (правило — решение владельца); одноразовое подтверждение + `Idempotency-Key` + аудит отказов; без автоматических повторов; WoL выключен по умолчанию и только в домашние диапазоны; BitLocker блокирует смену ОС до явного разрешения. Подробно — `docs/POWER.md`, ADR-014.

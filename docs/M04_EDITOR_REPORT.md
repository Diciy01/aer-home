# M04 Scene Editor — проверка и измерения

Дата: 2026-10-27. ПК: Ubuntu 24.04, GNOME Wayland (окно приложения через XWayland для xdotool), дискретная видеокарта среднего класса, монитор 1920×1080; Flutter 3.47.7 (Impeller), Flame 1.38.2, Go 1.27.3. Все проверки — против изолированного Core (`AER_DATA_DIR` во временном каталоге); объекты Registry, созданные тестами, помечены «(тест)».

## Что проверено вживую (реальное окно, реальный Core, мышь)
`integration_test/editor_live_test.dart` — один сквозной сценарий, проходит:
1. Демо-планировка сохраняется в Core; вход в режим строительства кнопкой «Редактировать дом».
2. Каталог: категория «Компьютеры», поиск «раст».
3. Размещение растения мышью: призрак, проверка, клик → предмет в гостиной.
4. Перетаскивание выделенного предмета мышью → одна запись в истории; клик по невыделенному столу его не двигает.
5. R — поворот, Ctrl+D — копия, Delete → подтверждение → удаление.
6. Привязка системного блока через мастер к «Домашний ПК (тест)»; карточка показывает имя из Registry; мини-сервер привязан к второму устройству.
7. «Новая комната» (камень, светлый шалфей) → Enter; размер тянется мышью за ручку (+1 м); освещение «Тёплый вечер»; стол в новую комнату.
8. 4× Ctrl+Z и 4× Ctrl+Shift+Z — документ побайтно совпадает с исходным.
9. Сохранение → ревизия выросла; документ в Core содержит новую комнату и привязку.
10. Конфликт: сцену меняют напрямую через API → «Сохранить» → диалог 409 → «Загрузить актуальную» → чужие изменения на месте, свои отброшены.
11. Несохранённая правка + черновик → **перезапуск** (новые контроллеры над тем же Core и каталогом данных) → сохранённая комната и привязка на месте, плашка «Найден несохранённый черновик» → «Восстановить» → правка вернулась.

Регрессия: `scene_live_test` (M03) и `registry_live_test` (M02, на чистом Core) — проходят. Release-сборка: вход в редактор, перетаскивание стола мышью (xdotool), выход — работают (`docs/screenshots/m04/14-release-window-drag.jpg`).

Найдено и исправлено замером: в режиме строительства с анимированными значками было 20 % CPU — Impeller в каждом кадре сцены заново рисовал ~30 векторных превью каталога с размытыми тенями и тени панелей. Превью рендерятся один раз в текстуры, тени панелей облегчены → 13 %. Без анимированных состояний движок спит, как в M03.

Изменённый существующий тест: Go `TestValidationRules` — случай «unknown floor = lava» заменён на «malformed floor = "Lava Rock"» и «malformed light»: с контракта 0.5.0 любой корректный идентификатор материала допустим по замыслу (материалы — данные), проверка формы осталась. Остальные тесты M01–M03 не менялись (в `house_view_test` добавлен только параметр стенда для черновика).

## Художественная часть
Не финальная. Проведён проход по единому стандарту (`docs/SCENE_ART_ASSETS.md`): эталонный кабинет перерисован (стол с тумбой и латунными ручками, монитор с тонкой рамкой и «рабочим столом», кресло с крестовиной и подлокотниками, лампа на кронштейне, растение в керамическом горшке, ковёр с орнаментом и бахромой, картина), добавлены 7 предметов. Всё процедурное и помечено `placeholder`; составлены требования и реестр изображений для финальных спрайтов и текстур.

## Известные ограничения
- Undo/Redo на 200 объектах — ~22 мс на шаг (см. выше).
- Предметы на стенах — только на внешних задних (север/запад) стенах; перегородки низкие (cutaway) и вешать на них нельзя.
- Повороты 0/90/180/270; дробные позиции — шаг 0,1 клетки (Alt).
- Перетаскивание комнаты меняет только положение; изменение размера — с ближних (восточной/южной) сторон.
- Импорт/экспорт JSON, восстановление старой ревизии из интерфейса, пользовательские каталоги и текстуры — не сделаны.
- Windows/мобильные клиенты не проверялись (UNVERIFIED).
